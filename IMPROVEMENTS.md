## 1. Архитектура и стабильность

### 1.1. Конфигурация через файл/env вместо констант в коде
**Проблема:** все настройки (`RAG_BASE_URL`, `TTS_SPEAKER`, `AUDIO_DEVICE`, `VAD_THRESHOLD` и т.д.) захардкожены в `voice_assistant.py`.

**Решение:**
- Вынести в `.env` / `config.yaml` / `config.json`.
- Использовать `python-dotenv` (уже в зависимостях).
- Пример:
```python
RAG_BASE_URL = os.getenv("RAG_BASE_URL", "http://localhost:5000")
TTS_SPEAKER = os.getenv("TTS_SPEAKER", "eugene")
```

### 1.2. Разнести код на модули
**Проблема:** `voice_assistant.py` — монолит на ~1100 строк (STT + VAD + RAG-клиент + TTS + логика).

**Решение:** разбить на пакет:
```
assistant/
├── __init__.py
├── config.py          # настройки
├── stt/               # KairosSTT, NemotronSTT
├── vad.py             # Silero VAD
├── rag_client.py      # RAGClient (WebRAgent API)
├── tts.py             # NeuralSpeaker
├── pipeline.py        # VoiceAssistant (оркестрация)
└── logging_utils.py   # log_question и пр.
```

### 1.3. Единая точка входа с обработкой ошибок
- Обернуть весь цикл в try/except с понятными сообщениями.
- Добавить `--verbose` флаг для отладки уровней.
- Логировать в файл + консоль (`logging` вместо `print`).

### 1.4. Graceful shutdown (корректное завершение)
- Останавливать потоки через `Event()` (не просто флаг `is_recording`).
- Дожимать текущую фразу перед выходом.
- Останавливать `arecord`, `ollama`, Docker в правильном порядке.

## 2. Распознавание речи (STT)

### 2.1. Загрузка модели один раз (лениво) — сделано, но улучшить
- Nemotron грузится лениво при первой фразе — хорошо.
- **Улучшение:** предзагружать модель при старте в фоновом потоке, чтобы первая фраза не ждала.

### 2.2. Двухпроходное распознавание для точности
- Сначала быстрый проход (Kairos / низкая задержка), затем, если нужно — Nemotron.
- Или: `--stt auto` — выбирать модель по длине фразы / уверенности.

### 2.3. VAD: параметры настраиваемые
- `VAD_THRESHOLD`, `SILENCE_TIMEOUT_SEC`, `MIN_SPEECH_DURATION_SEC` сделать CLI-флагами (сейчас часть захардкожена).
- Добавить адаптивный порог (подстраиваться под уровень шума).

### 2.4. Шумоподавление
- Сейчас `noisereduce` только если есть профиль шума.
- **Улучшение:** ресемплинг через `librosa` уже есть — можно добавить нормализацию громкости (RMS) перед распознаванием.

### 2.5. Потоковая транскрипция частичных результатов
- Пока распознаётся фраза, показывать промежуточные гипотезы (как в `nemotron_streaming_stt.py` — стриминг `TextIteratorStreamer`).

## 3. RAG / Поиск в интернете

### 3.1. Поисковики SearXNG — главная боль
**Проблема:** google/brave/duckduckgo/qwant заблокированы (CAPTCHA/rate limit), категория `general` даёт 0 результатов.

**Лучшие решения:**
1. **Использовать категорию `web`** (seznam, mojeek) — уже сделано в `searxng_service.py`.
2. **Добавить рабочие API-поисковики** как fallback:
   - SearXNG `yandex` (если доступен), `wttr.in` для погоды.
   - Google Custom Search JSON API (ключ), Bing Web Search API.
   - SerpAPI / Tavily (специально для LLM-агентов, есть бесплатный тариф).

### 3.2. Улучшить `process_query` в SearXNGService
- **Deduplicate** результатов по URL.
- Сортировать по релевантности/языку.
- Добавить извлечение «answer box» (погода, факты) — SearXNG отдаёт `infoboxes`/`answers`, сейчас они игнорируются.
- Для «погоды» парсить `infoboxes` — там часто готовая температура.

### 3.3. Гибридный поиск (RAG + Web)
- Сначала искать в коллекции МИРЭА (если вопрос про МИРЭА), иначе — интернет.
- **Улучшение:** искать и там, и там, потом объединять результаты с весами.

### 3.4. Параллельные запросы
- Делать несколько подзапросов (агентный поиск) параллельно, а не последовательно — быстрее.

## 6. Инфраструктура и деплой

### 6.1. Docker: монтировать код, а не зашивать в образ
**Проблема:** `docker-compose.yml` использует готовый образ `ghcr.io/dkruyt/webragent:latest` и монтирует только `./data`. Любые правки в `app/` требуют пересборки.

**Лучшее решение:** монтировать локальный код:
```yaml
services:
  app:
    build: .
    volumes:
      - ./app:/app/app   # горячая перезагрузка кода
      - ./data:/app/data
    environment:
      - FLASK_DEBUG=1
```
Тогда правки применяются без пересборки (Flask debug перезагружает).

### 6.2. systemd / supervisord для автозапуска
- `run_all.sh` поднимает стек вручную.
- **Улучшение:** unit-файлы systemd (`webragent.service`, `ollama.service`) с `Restart=always`.

### 6.3. Скрипт установки одной командой
- `setup.sh`: установить зависимости, создать env, собрать модель, поднять Docker.
- Проверять предварительные условия (Docker, CUDA, arecord, микрофон).

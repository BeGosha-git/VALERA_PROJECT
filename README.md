# 🎙️ Голосовой ассистент «Валера» (Микрофон → RAG → TTS)

Полноценный голосовой ассистент в стиле экскурсовода РТУ МИРЭА.
Распознаёт речь с микрофона, ведёт диалог с контекстом через RAG/LLM
и озвучивает ответ.

```
Микрофон → [STT] → текст вопроса → [WebRAgent / Ollama RAG] → ответ → [TTS] → динамики
```

---

## 📋 Быстрый старт

Всё запускается одной командой:

```bash
./run_all.sh web                  # ⭐ рекомендуемый способ
```

Откроется **веб-пульт** на «невзрачном» порту **8137** → http://localhost:8137
Его можно открыть и с телефона/планшета (см. `--web-host 0.0.0.0`).

| Режим | Что делает |
|---|---|
| `talk` | Запускает `TALK.py` (простой диалог, по умолчанию) |
| `web` | ⭐ **Веб-пульт** в браузере (полностью заменяет настольный GUI) |
| `voice` | Голосовой ассистент **с подтверждением** вопроса перед запросом |
| `voice-fast` | Голосовой ассистент **без подтверждения** (сразу отвечает) |
| `gui` | Настольное окно (Tk) — если нужен именно оно |
| `kb-ingest` | Залить **базу знаний РТУ МИРЭА** в WebRAgent (разово) |
| `reset` | Сбросить состояние: логи, настройки, при `--chats` — чаты |

### Первый запуск: подключить базу знаний МИРЭА

Архив с базой знаний лежит в `knowledge_base/rtu_mirea_llm_kb.zip` (распаковывается
автоматически). Загрузите его в WebRAgent одной командой:

```bash
./run_all.sh kb-ingest                # залить фрагменты + FAQ + таблицы
./run_all.sh kb-ingest --with-full    # плюс полный документ (≈400 КБ)
./run_all.sh kb-ingest --reset-kb     # пересоздать коллекцию «МИРЭА» с нуля
```

Скрипт создаёт коллекцию **«МИРЭА»** и заливает 85 документов (79 фрагментов,
FAQ, таблицы, ключевые факты). После этого любые вопросы про МИРЭА ищутся
**офлайн — по локальной базе**, а не в интернете.

## 💻 Веб-пульт (рекомендуется)

```bash
./run_all.sh web                      # http://localhost:8137
./run_all.sh web --web-host 0.0.0.0   # доступ с других устройств сети
./run_all.sh web --web-port 9000      # другой порт
./run_all.sh web --stt nemotron       # сразу на Nemotron
```

Порт по умолчанию — **8137**: он не бросается в глаза и маловероятно, что кто-то
его угадает. Веб-пульт **полностью заменяет** настольный GUI — весь функционал
доступен в браузере, включая работу с планшета или телефона рядом с роботом.

На вкладках:

- **Звук и чувствительность** — тумблеры функций (шумодав, авто-чувствительность,
  веб-поиск, база МИРЭА, barge-in, TTS, пересказ, триггеры, авто-новый чат),
  ползунки порогов и **живая визуализация**: что пришло с микрофона → что вырезал
  шумодав → что ушло Валере, плюс осциллограф и шкала уровня с порогом гейта.
- **Устройства и сеть** — выбор **микрофона** (`arecord -L`), **колонок**
  (`aplay -L`) и **сетевого интерфейса** для связи с роботом. Применяется на лету.
- **Триггеры «слово → команда»** — таблица правил: ключевое слово и `curl`-команда.
  Можно добавить/изменить/удалить, включить-выключить и **проверить** без микрофона.
- **Чаты и контекст** — статистика чатов, **авто-новый чат по тишине**,
  **кнопки удаления старых/выбранных/всех чатов**.
- **Журнал** — поток событий (что услышали, куда ушёл запрос, что ответил робот).

### Настольный GUI (по желанию)

```bash
./run_all.sh gui                      # окно Tk
python valera_gui.py --no-autostart   # только пульт, без микрофона
```

Тот же набор функций в отдельном окне: тумблеры, графики, устройства, чаты,
и **диалог редактирования правила** — двойной клик по строке таблицы.

### Опции (передаются после режима)

| Опция | Описание |
|---|---|
| `--stt kairos` | Лёгкая модель распознавания речи (по умолчанию) |
| `--stt nemotron` | NVIDIA **Nemotron 3.5 ASR** — точнее, но тяжелее (GPU) |
| `--stt auto` | Автовыбор: короткие фразы → kairos, длинные → nemotron |
| `--web-port N` | Порт веб-пульта (по умолчанию 8137) |
| `--web-host H` | Адрес веб-пульта; `0.0.0.0` — доступ из сети |
| `--keep-ollama` | **Не** перезапускать Ollama (пригодится, если вы запустили её сами) |
| `--new-chat` | Начать **новый** разговор (сбросить контекст) |
| `--no-clean` | **Не** чистить текст вопроса (имена и мат сохраняются в запросе) |
| `--barge-in` | Прерывать озвучку ответа, если пользователь начал говорить |
| `--no-auto-vad` | Выключить авто-регулировку чувствительности (ручной порог) |
| `--speaker ИМЯ` | Голос TTS (`eugene`, `xenia`, `aidar`, `baya`, `kseniya`) |
| `--vad-threshold N` | Порог VAD (0..1, ниже = чувствительнее) |
| `--silence-timeout N` | Пауза тишины перед концом фразы (сек) |
| `--with-full` | (только `kb-ingest`) залить и полный документ базы знаний |
| `--reset-kb` | (только `kb-ingest`) пересоздать коллекцию «МИРЭА» |
| `--chats` | (только `reset`) удалить все чаты WebRAgent из MongoDB |
| `--dry-run` | (только `reset`) показать, что будет удалено |
| `--proxy URL` | HTTP-прокси для исходящих запросов. Пример: `--proxy http://127.0.0.1:12334` |

> 🔥 **Полный прогрев ИИ-моделей (STT + LLM) выполняется автоматически при каждом
> старте** в фоновом потоке — первый вопрос не ждёт загрузки моделей в память.

### Примеры

```bash
# Голосовой ассистент на Nemotron, без подтверждения, новый чат каждый раз
./run_all.sh voice-fast --stt nemotron --new-chat

# Голосовой ассистент на Kairos с подтверждением
./run_all.sh voice --stt kairos

# Использовать уже запущенную Ollama (не перезапускать)
./run_all.sh voice-fast --stt nemotron --keep-ollama

# Отправлять в ИИ текст вопроса БЕЗ очистки (имя/мат сохраняются)
./run_all.sh voice-fast --stt nemotron --no-clean

# Использовать HTTP-прокси (например, системный из GNOME 127.0.0.1:12334)
./run_all.sh voice-fast --stt nemotron --proxy http://127.0.0.1:12334
```

> 🌐 **Про прокси.** Если поиск в интернете не находит нужное (движки Google/Yandex
> блокируют запросы из Docker), можно направить трафик через локальный прокси:
> `--proxy http://127.0.0.1:12334`. Прокси автоматически подставляется:
> 1. **Контейнеру SearXNG** — исходящие запросы к поисковикам идут через него
>    (внутри Docker адрес хоста подменяется на `host.docker.internal`);
> 2. **Приложению** (переменные `HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY`);
> 3. **Ollama** (если ей нужен доступ в интернет для скачивания моделей).
>
> Замечание: даже через прокси Google/Yandex могут возвращать пустые результаты
> (CAPTCHA/блокировки). Надёжно работают `bing` и `mwmbl` — они используются
> по умолчанию и дают релевантные результаты (погода, новости и т.п.).

> ⚡ **Про скорость.** Поиск оптимизирован: рабочие движки пингуются и опрашиваются
> **параллельно** (не последовательно), а мусорные (seznam, presearch и др.) —
> исключены. Ответ на простой вопрос занимает ~2 секунды, сложный (сравнения,
> несколько вопросов) — ~5 секунд.

## 🚀 Что запускает `run_all.sh`

Скрипт автоматически поднимает весь стек:

1. **Conda-окружения** — создаёт `tts_env` и `mic_to_text_env`, если их нет.
2. **Ollama** — **останавливает все чужие процессы** `ollama serve` и запускает
   собственную копию с моделью `valera_live:latest` (персона «Валера»).
   Чтобы НЕ трогать чужую Ollama — передайте `--keep-ollama`.
3. **WebRAgent** (Docker Compose) — веб-интерфейс, RAG, MongoDB, Qdrant, SearXNG.
4. **Приложение** — `voice_assistant.py` или `TALK.py`.

При завершении (Ctrl+C) скрипт корректно останавливает Docker-сервисы
и **собственную** Ollama (чужую — не трогает).

## 🧠 Про контекст разговора

Контекст вопросов и ответов хранится **на сервере WebRAgent** (в MongoDB),
а не в самом скрипте.

Ассистент общается с моделью через **серверный чат** WebRAgent
(`/chat/<chat_id>/query`), а не через «прямой» поиск. Это принципиально:
серверный чат сохраняет каждую реплику и сам подставляет историю диалога
как контекст, поэтому модель действительно помнит предыдущие вопросы
и ответы. Прямой `/query` с ручной передачей истории так себя не ведёт —
на вопрос «что я спрашивал раньше?» он отвечает неверно.

```
Голос → STT → вопрос → WebRAgent /chat/<chat_id>/query
                              │
                              ├── история (MongoDB) → контекст в промпт
                              └── поиск (база МИРЭА / интернет) → ответ
                                        │
                                        └── сохраняется в тот же чат
```

- При первом запуске создаётся чат, его `chat_id` сохраняется в файл
  `chat_id.txt` в корне проекта.
- При следующих запусках ассистент **продолжает тот же чат** — модель помнит
  предыдущие вопросы и ответы. Если чат на сервере пропал (перезапустили
  MongoDB), ассистент автоматически создаст новый.
- Чтобы **начать новый разговор** (сбросить контекст) — используйте флаг
  `--new-chat`:

```bash
./run_all.sh voice-fast --stt nemotron --new-chat
```

### Авто-новый чат по тишине

Если гость отошёл и в разговоре наступила длинная пауза, контекст прошлой
беседы только мешает. Ассистент умеет **сам начинать новый чат** после
заданного времени тишины:

- Настройка: `valera_config.json` → `rag.auto_new_chat_after_silence_sec`.
- В веб-пульте/на GUI: вкладка **«Чаты и контекст»** → тумблер
  «Авто-новый чат» + поле «Тишина до нового чата, сек».
- `0` — выключено. Для экскурсий удобно **60 секунд**.

### Удаление старых чатов

Со временем в MongoDB копятся десятки чатов от прошлых сессий. В веб-пульте
и GUI (вкладка **«Чаты и контекст»**) есть кнопки:

| Кнопка | Что делает |
|---|---|
| **Новый чат сейчас** | Сбросить контекст немедленно |
| **Удалить старые** | Удалить чаты старше N дней (текущий не трогается) |
| **Удалить выбранные** | Удалить отмеченные галочкой чаты |
| **Удалить все** | Вычистить всю историю, кроме текущего чата |

Из командной строки — `valera_reset.py`:

```bash
./run_all.sh reset                 # логи + настройки + все чаты
./run_all.sh reset --dry-run       # посмотреть, что удалится
python valera_reset.py --chats -y  # только чаты, без вопросов
```

### Устройства ввода/вывода и сеть

Выбор **микрофона**, **колонок** и **сетевого интерфейса** — в веб-пульте и GUI
на вкладке **«Устройства и сеть»** (применяется на лету). Там же кнопка
«Обновить списки», если устройство подключили уже после запуска.

- Микрофоны берутся из `arecord -L`
- Колонки — из `aplay -L` (голос Валеры пойдёт именно сюда!)
- Сетевые интерфейсы — из `ip addr` (виртуальные docker/veth скрыты)

Всё это хранится в `valera_config.json` → `audio.input_device`,
`audio.output_device`, `network.interface`.

Все заданные вопросы и ответы пишутся в лог `questions.log` (формат JSON —
одна строка на запись). Там видно: что услышали с микрофона, что ушло в ИИ,
куда именно ушло (`chat` / `query` / `direct`), ответ и id чата с контекстом.

### Обработка ответов через ИИ 🧠

Сырые ответы RAG/веб-поиска (со ссылками и сниппетами) **пересказываются
локальной моделью Ollama** (`rephrase_answer_with_ai`) в живой разговорный
текст перед озвучкой — без URL и служебной информации. Настраивается через
`.env`:

```ini
OLLAMA_URL=http://localhost:11434
REPHRASE_MODEL=valera_live:latest
```

### Очистка текста вопроса

По умолчанию ассистент **очищает** распознанный текст перед отправкой в ИИ
(через `clean_question`): удаляет обращение «Валера» и нецензурную лексику.

Чтобы отправлять текст **как есть** (без очистки) — используйте `--no-clean`:

```bash
./run_all.sh voice-fast --stt nemotron --no-clean
```

## 🛠️ Требования

- **Linux** с `alsa-utils` (`arecord`), Docker, Conda
- **NVIDIA GPU** (рекомендуется) — для Nemotron STT и ускорения LLM
- **микрофон** (лучше USB, например DJI MIC MINI) и **динамики**

### Микрофон

Захват идёт через `arecord -D default` (PipeWire/Pulse), что надёжно работает
с USB-микрофонами. По умолчанию используется устройство `default`.
Устройство можно сменить в `voice_assistant.py`:

```python
AUDIO_DEVICE = "default"          # например: "plughw:CARD=MINI,DEV=0"
```

Посмотреть доступные микрофоны:
```bash
arecord -L
```

## 🧪 STT-модели распознавания речи

### Kairos (по умолчанию, лёгкая)
- Работает на CPU/GPU, быстрая, средняя точность.
- Не требует отдельных зависимостей кроме `mic_to_text/environment.yml`.

### Nemotron 3.5 ASR (точная)
- NVIDIA-модель, требует GPU (проверено на RTX 5070 Ti / 5060 Ti).
- **Важно**: для Blackwell (RTX 50xx) нужен PyTorch `cu128+`.
  В `mic_to_text_env` уже стоит `torch 2.13+cu130` (от kairos), поэтому
  Nemotron работает прямо в этом окружении.
- Задержка стриминга задаётся `NEMOTRON_LATENCY_MS`
  (поддерживается 80 / 320 / 560 / 1120 мс).
- Реализация живёт в `nemotron_asr/nemotron_streaming_stt.py`
  (класс `NemotronStreamingASR`). `voice_assistant.py` **переиспользует** этот
  код через тонкую обёртку, а не дублирует декодер.

```bash
# Оба варианта используют один и тот же движок распознавания
./run_all.sh voice-fast --stt nemotron    # всегда Nemotron
./run_all.sh voice-fast --stt auto        # короткие → kairos, длинные → nemotron
```

## 🐛 Диагностика

### Не слышно голоса / ничего не распознаётся

1. Проверьте, что микрофон виден: `arecord -L`
2. Если распознавание пустое — уровень громкости слишком низкий.
   Проверьте уровень:
   ```bash
   arecord -D default -d 3 -f S16_LE test.raw && python3 -c "
   import numpy as np
   a = np.frombuffer(open('test.raw','rb').read(), dtype=np.int16)/32768
   print('peak:', np.abs(a).max())"
   ```
   Если peak < 0.05 — поднесите микрофон ближе или увеличьте громкость.

### Ollama перезапускается каждый раз

Это ожидаемо: `run_all.sh` по умолчанию останавливает внешнюю Ollama
и запускает свою. Чтобы сохранить свою — используйте `--keep-ollama`.

### Контекст разговора не работает

- Убедитесь, что WebRAgent запущен: `curl http://localhost:5000/auth/login`
- Убедитесь, что `chat_id.txt` существует. Если он удалён — создастся новый чат.
- Проверьте содержимое `questions.log` — там видны все запросы/ответы.

## 📝 Примечания по перезапуску Ollama

`run_all.sh` по умолчанию:

1. Находит все процессы `ollama` командой `pgrep -f "ollama"`.
2. Останавливает их (кроме своих собственных процессов скрипта).
3. Запускает свежий `ollama serve` для проекта.
4. Убеждается, что модель `valera_live:latest` создана (из `Modelfile`).
5. При выходе останавливает только **свою** Ollama.

Если Ollama нужна вам и вне этого проекта — запустите её отдельно и передайте
`--keep-ollama`, чтобы скрипт её не трогал.
